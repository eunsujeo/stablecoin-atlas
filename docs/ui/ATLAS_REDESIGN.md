# 저장 자료 중심 Atlas 재설계

2026-10-24 사용자 요청: 가격 표시 설계를 진행하고 확보한 자료를 기준으로 UI를 처음부터 다시 설계한다. [frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)의 계획·대조·구현·비평 절차를 적용한다. 로컬 전용이며 [ADR0085](../adr/0085-stored-data-ui-redesign.md)가 범위를 고정한다.

## 목적과 정보 구조

이용자는 스테이블코인의 규모·체인별 차이·지갑 간 이동과 확보 근거를 구분해서 살펴본다. 첫 화면은 동일한 정의의 공급량 비교를 중심으로 한다. 화면 순서는 공급량, 전송량, 가격, 조사 범위다. 코인 전체 유통량과 체인별 총공급량은 다른 표·그래프에 놓는다. 기술 검증은 기존 근거 화면으로 연결한다.

```text
Atlas   공급량  전송량  가격  조사 범위       테마 / 저장본 다시 읽기
스테이블코인의 규모와 이동                   저장본 조회 상태
┌코인 선택 / 기간──────────────────────┬코인 전체 유통량────┐
│체인별 총공급량의 실제 저장 이력       │같은 통화 안의 비교│
│점 선택 → 원래 수량과 시각             │출처 / 시각 상세   │
└──────────────────────────────────────┴───────────────────┘
자료 정의 / 해당 자료 없음 / 기존 근거 이동
```

왼쪽 정렬·넓은 그래프와 좁은 비교 목록을 사용한다. 모바일에서는 그래프, 목록 순으로 쌓는다. 상단 탐색은 화면을 실제로 전환한다. 새 공급자 호출을 뜻하는 실시간 표시나 재생 아이콘을 쓰지 않는다.

## 시각 계획과 대조

색은 다크의 ink `#e6edf5`, canvas `#142235`, panel `#1b2d43`, line `#40536a`, blue `#80bfff`, amber `#f1c778` 여섯 가지로 시작한다. 라이트는 canvas `#edf2f8`, panel `#ffffff`, ink `#172b43`, line `#bdcbdc`, blue `#175eb8`, amber `#78530d`로 대응한다. 공급량의 선 색은 기존 검토 차트의 네트워크 식별색을 유지한다.

글꼴은 로컬 Avenir Next와 한국어 Apple SD Gothic Neo/Malgun Gothic을 사용한다. 본문 15px, 제목 32px, 표 14px, 도움말 13px이며 수량은 tabular 숫자다. 외부 폰트·아이콘·이미지를 요청하지 않는다. 여백은 8/16/24/32px, 조작부와 영역의 모서리는 각각 8/16px다.

초안의 대형 가격·등락 KPI는 통화·기준시각 미확인 표본에 잘못된 권위를 줄 수 있어 제거했다. 같은 크기 카드 나열 대신 공급량 그래프를 중심으로 비교 목록과 정의를 배치한다. 강조는 선택한 코인의 파란색 조작부에 집중한다. UNKNOWN은 노란 도움 문구와 명시 텍스트로, 확보되지 않은 값은 빈 상태로 표현한다. 장식용 그라데이션과 자동 모션은 없다.

## 가격 표시 계약

| 자료 | 화면에서 허용하는 것 | 계산·표시 제한 |
| --- | --- | --- |
| 기존 승인된 시장 projection PRICE | 기존 USD 단위 계약의 저장 가격 문자열, 실제 sourceAt 또는 기준시각 미제공, 개별 요청시각, 공급자 | 현재가·새 표본으로 해석하지 않음. 환산·새 시장 총액·디페그 판정 없음 |
| Allium 가격/이력/통계 3종 | 연구 확보 상태, Ethereum USDC 대상, 필드명, 통화·창 정의 미확인 | 원문 수치·주소·receipt 공개 없음. 통화 UNKNOWN에서 $·KRW·등락률·OHLC·시계열 연결 없음 |
| Arkham 접근 표본 시장/이력 | 시장 필드14개와 이력1225점이라는 당시 검토 사실, 자체 식별·기준시각 한계 | 기존 승인 시장 projection에 섞거나 최신값으로 승격하지 않음 |

입력은 기존 검증 모듈이 허용한 projection만 받는다. 금액은 십진 문자열로 유지하며 순서 비교는 bigint를 쓴다. null은 `—`, 행 부재는 `저장된 자료 없음`, 읽기 실패는 실패 메시지와 이전 정상 자료로 구분한다. 연구 표본의 상태는 FIELD_CONTRACT_OBSERVED이며 제품 PASS가 아니다. 요청시각·조회완료 시각을 공급자 기준시각으로 쓰지 않는다.

## 자료별 연결

- 공급량: 기존 `/market-data.json`의 코인 전체 CIRCULATING과 CHAIN_TOTAL 이력만 사용한다. 자산·기간 선택과 통화별 정렬을 제공한다. XRPL obligations는 체인 총공급량 그래프에 섞지 않는다.
- 전송량: 기존 `/activity-data.json`이 설정된 경우만 기존 검증을 거쳐 사용한다. provider day·tokens·USD·건수를 분리하며 매매 거래량이라고 부르지 않는다. JSON 모드에서 경로가 비활성이면 그대로 설명한다.
- 조사 범위: [검토 정본](../research/provider-data-use-priorities-2026-10-24.md)의 고정 연구 요약만 표시한다. 11배포·7일·70/67관측은 과거 검토 snapshot 한 쌍의 범위이며 현재 endpoint 행 수나 누적274관측과 혼동하지 않는다. SQL probe_id는 시계열이 아니며 지갑형 주소는 토큰 컨트랙트다.
- 기술 검증: 기존 `/legacy.html#validation`, `/legacy.html#reports`로 이동한다. 등급·지원 인증을 새로 산정하지 않는다.

## 조사 범위에서 근거를 찾는 흐름

2026-10-24 사용자가 자산 프로필·자산 비교 연결과 화면 기획 후 구현을 승인했다. 조사 범위의 첫 영역은 사용 목적에 따라 근거를 찾는 진입점으로 구성한다. 두 번째 영역에는 기존 자료 확보 기록과 해석 한계를 그대로 둔다.

| 위치 | 표시와 목적 | 이동 |
| --- | --- | --- |
| 첫 영역의 주요 선택 | 자산 프로필: 자산·체인별 저장 보고서와 항목별 근거 확인 | `/legacy.html#assets` |
| 첫 영역의 주요 선택 | 자산 비교: 같은 자료 범위에서 2~3개 보고서의 시나리오 비교 | `/legacy.html#compare` |
| 주요 선택 아래 보조 링크 | 기술 검증: 개별 판정·미확인 항목 탐색 / 근거 보고서: 보존된 문서 확인 | 기존 validation / reports hash |
| 두 번째 영역 | 자료 확보 기록: 당시 연구 표본의 확보 상태와 의미의 한계 | 기존 고정 표 유지 |

주요 선택은 설명이 있는 큰 텍스트 링크 두 개로 배치하고, 모바일에서는 한 열로 쌓는다. 마우스·키보드 모두 같은 문서 내 링크처럼 사용할 수 있는 기본 anchor를 사용한다. 기존 근거 화면의 제목 옆에 `Atlas 조사 범위로` 링크를 두어 `/#coverage`로 돌아온다. 브라우저 뒤로 가기도 유지한다. 새 탭을 강제하지 않는다.

진입점은 시장 자료의 로딩·실패와 독립적으로 사용할 수 있다. 여기에 보고서 수·지원 등급·통과 점수를 새로 산정하거나 자산을 자동 선택하지 않는다. 자산/체인 식별과 비교 항목은 기존 화면이 읽는 공개용 근거 projection에서 확인한다. 체인별 권한 의미가 다르다는 기존 설명과 UNKNOWN·NOT_TESTED를 보존한다. 새 endpoint·parser·외부 요청·DB 입력은 없다.

## 검증과 후속

2026-10-24 후속 사용자 승인으로 `/`와 `/index.html`은 Atlas를 기본 화면으로 제공한다. `/atlas.html`은 같은 화면의 별칭이며, 기존 화면은 `/legacy.html`에 보존한다. Atlas의 기술 검증·보고서·시장 상세 링크는 기존 화면의 해당 hash로 연결하고, 기존 화면에는 Atlas 홈 링크를 둔다. 기존 화면의 공유 query는 `/legacy.html?...`에서 유지한다.

`/`에서 기본 화면과 기존 화면 간 이동을 확인한다. 스크린리더용 상태·표 제목, 키보드 탭/방향키, 모바일, 다크/라이트, 실패 후 마지막 자료 보존을 검증한다. 고정 문서 경로만 길이 제한 안의 query를 허용하며 API·정적 자산의 허용목록은 유지한다. 원격 DB 접속이나 실제 수집 없이 로컬 JSON 모드와 합성 오류 주입으로 시험한다. 연구 자료의 새 정규화·DB 입력과 추가 자료 연결은 후속 범위로 남긴다.
