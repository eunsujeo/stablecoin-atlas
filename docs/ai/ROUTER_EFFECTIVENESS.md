# Router 효과 관측 — 2026-10-19

현재 **모델 선택·토큰 절감 효과는 입증되지 않았다.** 로컬 추천과 Lead 검토 요청/응답은 작동하지만, 자동 모델 전환은 구현·활성화되지 않은 shadow 모드다. 설정은 변경하지 않았다.

## 저장된 추천 16건

`tools/intelligent-router/.state/routes/*.json`의 누적 로컬 기록을 집계했다. 이 대화만의 표본이나 독립 정답이 있는 평가셋은 아니다. 재분류·모델 재실행 없이 기존 기록만 읽었고 파싱 오류는 0건이었다.

wall은 모델 적재·검증을 포함한 Adapter 시간이다. 분류 연산만의 시간이나 GPT 작업 완료 시간과 다르다. confidence는 보정된 작업 성공 확률이 아니다. 로컬 모델의 `raw.usage`를 Codex 사용량으로 합산하지 않았다.

모든 추천이 같은 Advanced로 귀결되어 현재 표본에서는 저비용 모델을 구별해 선택하는 효과가 없다. 실제 실행 모델·토큰·수동 기준과의 연결도 없으므로 절감률을 계산할 수 없다. 약 6초의 요청 처리 비용은 관측되었으나 사용자 체감 지연 전체를 측정한 값은 아니다.

## Lead 검토

집계 시점의 요청은 7건: 응답 완료 6건(연결 smoke 1건 + 실제 검토 5건), 이번 0 transferFrom 검토 1건은 진행 중이었다. 완료 응답은 모두 proceed였다. Router 추천 기록과 Lead 요청을 동일 작업 ID로 연결하는 계측은 없다.

작업 종료 시 이번 요청 `21cd03f819c240a1977b2ca4ac3397bd`도 answered/proceed로 회수했다. 최종 7건 모두 응답 완료(연결 smoke 1건 + 실제 검토 6건)이며 미회수 검토는 없다. 이번 조건 중 승인 전제 실패 시 0 거래 미전송, 승인 후 상태 기준 설정, allowance 차감 부정 Fixture를 구현·검증에 반영했다.

실제 검토 조건을 구현에 반영한 사례는 오류 원문 제거 후 명시적 revert 분류 유지, 원자적 파일 저장의 권한·링크·정리 실패 처리, 블록 번호·헤더 일치 및 이전 참조 초기화, 0 전송에서 관측 실패와 실행 실패 구별이다. 따라서 **검토 절차가 작동하고 조건이 반영된 사실**은 확인된다. 대조군·검토 전후 독립 품질 점수가 없어 버그 감소율이나 시간 절약을 주장할 수는 없다. Lead 호출 자체에도 GPT turn이 사용된다.

## 다음 평가 조건

현재 shadow를 유지한다. 명확한 작업 요약·필요한 짧은 코드 문맥과 독립 정답 라벨을 갖춘 평가셋에서 fallback 비율과 고위험 누락을 먼저 측정한다. confidence가 낮다는 이유만으로 Lead를 호출하거나, 추천 분산을 만들려고 임계값을 낮추지 않는다.

이후 동일 작업 ID로 추천·실제 모델·최종 테스트·재시도·회수 가능한 실제 사용량을 연결하고 수동 기준과 비교해야 절감 및 품질 효과를 판단할 수 있다. 사용량을 얻지 못하면 null을 유지한다. 기존 [오프라인 8건 평가](ROUTER_EVALUATION.md)와 이번 누적 16건은 서로 다른 표본이므로 합산하지 않는다.
