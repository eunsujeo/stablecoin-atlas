# ADR0056: 공급량 규모 가독성과 일별 자료 재사용

- 상태: 구현
- 기준: 2026-10-23
- 선행: [확장 Overview](0054-registered-supply-overview.md), [일별 수집](0055-registered-daily-collection.md)

## 축과 화면

Overview 기본 비교를 공급량 규모로 한다. 여러 네트워크의 양수 최댓값이 최솟값의100배 이상이면 bigint로 판정해 자동 로그 눈금을 적용한다. 양수는10진 지수 눈금이고 실제0은 로그 구간 아래20px 떨어진 별도0 기준선이다. 이 비선형 눈금/0 표시는 차트에 안내한다. 단일 네트워크·격차 작은 값·전부0은 기존 선형축, 증감률은 기존 첫 관측 대비 계산을 유지한다. Number는 화면 좌표에만 사용하며 원본·툴팁 금액은 정확한 십진 문자열이다. 누락 날짜·실제0·단일 관측을 구분한다.

오른쪽 목록은 차트 높이 내에서 스크롤하며 '상위 최대10개 네트워크'와 실제 표시 개수를 안내한다. 선정 기준은 저장된 USD 환산 유통가치이고, 현재 목록의 정렬/숫자는 선택한 유통량 또는 발행 잔액의 tokens다. 선정 기준 설명은 제목 tooltip으로 구분한다. 상위10 미만을 가짜 항목으로 채우지 않는다. scope는 '일별 유통량 · USD/JPY 연동' 정도로 줄이고 대시보드의 출처 문구를 제거한다.

## 일별 자료 재사용과 오류

외부 수집 주기는 ADR0055 그대로다. 화면 새로고침은 공급자를 호출하지 않는다. 브라우저는 selection/coin/metric/sourceId/from/to가 모두 같은 현재 detail을 재사용해 수동 버튼·60초 갱신에서 history fetch를 생략한다. 새 응답도 같은 pin 전부를 검사해 index와 history 사이 갱신을 잘못 수락하지 않는다. 실패 시 이전 시각을 유지하고 오류를 표시하며 새 자료로 바꾸지 않는다.

서버는 현재 index를10초 캐시하고 만료하면 DB 권한/구조/선정을 먼저 다시 검증한다. 불변 history는 위 전체 pin 키로1시간/최대10건/직렬화8MiB 안에서 재사용한다. hit로 TTL을 늘리지 않으며 오래된 항목을 제거한다. index 실패 시 이전 history를 정상 반환하지 않는다. 반환 DB DTO의 pin도 검사하고 실패 응답은 저장하지 않는다. 동시 요청 병합·연결1개·대기4건·응답2MiB 제한은 유지한다.

history HTTP는 `private, no-cache`와 실제 DTO bytes SHA256 ETag를 사용한다. 브라우저 F5도 서버 index 확인 뒤 같은 DTO이면304로 본문 재전송을 피한다. index와 실패 응답은 계속 no-store다. 서버 재시작/캐시 만료 시에는 DB를 다시 읽으며 수집 API를 실행하지 않는다.

## 기본정보 연결

검증된 DB metadata에서 코인별 검토일·공식 링크·선정 네트워크·새 JPY 계약 프로필을 index에 추가한다. 브라우저에서 URL host/주소/표준을 검사한다. 기존3코인 프로필은 기존 DB catalog를 읽은 market 결과를 이용한다. 제목의 토큰명과 네트워크ⓘ에 hover/focus/tap/Escape popover를 연결한다. 확인하지 못한 네트워크의 주소·표준을 추측하지 않고, market aggregate에 가짜 deployment를 만들지 않는다. 공식 확인 링크는 기본정보 안에 유지한다.

## 검증

100배 경계·극소수/큰수·0/단일점/공백·증감률 회귀, cache 전체 pin·1시간 비연장·개수/바이트 제한·실패 재검증, HTTP ETag/304/HEAD/오류, 브라우저의 수동/60초/F5 갱신·목록 스크롤·토큰 기본정보·모바일을 검사한다. DB schema/수집기/예약/금액 원본은 변경하지 않는다. 결과와 실행 중 프로세스는 최신 인계문을 따른다.

## 새로고침 선택 유지

브라우저의 versioned `atlas-overview-chart-v1`에 coin/network/source/period/comparison UI 선택만 저장한다. 금액·원문·인증정보는 저장하지 않는다. 허용값/길이/JSON 버전을 검사하고 저장소 읽기·쓰기 거부는 화면 실행을 막지 않는다. 첫 index와 history가 로딩되기 전의 빈 선택 목록이나 실패 응답으로 저장 네트워크를 지우지 않는다. 정상 source pin에 맞는 history를 확보한 후 가용 네트워크를 확인해 복원하거나 모든 네트워크로 되돌린다. 사용자 변경은 단일 선택 state에 즉시 반영하며 과거 복원이 새 선택을 덮지 않는다. 토큰/source의 정상 옵션 제거 시에는 가용 항목으로 되돌린다. F5·전체 다시 읽기·60초 갱신·순위 목록 직접 선택 모두 같은 상태를 사용한다.
