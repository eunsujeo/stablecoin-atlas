# ADR 0006 — 보고서 파일의 완성 후 교체

날짜: 2026-10-19. 상태: 채택.

## 문제

CLI의 writeFile은 기존 목적 파일을 먼저 비우므로 쓰기 실패 시 이전 보고서가 손상될 수 있다. mode 옵션은 이미 존재하는 파일의 권한을 좁히지 않으며 최종 경로가 심볼릭 링크이면 링크 대상을 따라간다. 증거 보고서는 완성된 파일 단위로 교체할 필요가 있다.

## 결정

JSON 직렬화가 끝난 뒤 목적 파일과 같은 상위 디렉터리에 프로그램 소유의 비공개 임시 디렉터리를 만든다. 새 파일을 배타적으로 0600 권한으로 열고 write/sync/close를 완료한 후 rename으로 목적 파일을 교체한다. 최종 경로에서 관측한 심볼릭 링크와 일반 파일이 아닌 대상은 거부한다. 기존 일반 파일은 권한이 넓어도 새 비공개 파일로 교체하며 hardlink의 다른 이름은 수정하지 않는다.

umask가 제한적이어도 새 임시 디렉터리와 파일에만 각각 0700/0600을 설정한다. 기존 상위 디렉터리나 목적 파일을 미리 chmod하지 않는다. lstat는 ENOENT만 무시하며 EACCES 등 다른 오류는 저장 실패로 처리한다. 끊어진 링크와 FIFO도 기록 대상으로 열지 않는다.

처리 가능한 실패에서는 자신이 생성한 임시 디렉터리만 정리한다. 저장 전 평가/직렬화 실패나 rename 전 저장 실패는 이전 목적 파일을 변경하지 않는다. 기존의 파일을 따로 지우거나 대체 경로로 직접 쓰는 fallback은 두지 않는다. 저장 오류 메시지는 경로·원문 예외를 포함하지 않는 고정 진단을 사용한다.

## 한계

신뢰된 로컬 상위 디렉터리와 rename을 지원하는 파일시스템을 전제로 한다. 같은 경로에 여러 writer가 저장하면 마지막으로 완료한 rename의 전체 내용이 남는다. 잠금·충돌 감지·병합·순서 보장은 제공하지 않는다. 부모 경로의 심볼릭 링크나 공격자가 디렉터리를 교체하는 상황을 막는 파일시스템 sandbox는 아니다.

lstat는 한 시점의 검사다. 검사 후 다른 프로세스가 최종 이름이나 부모를 바꾸는 경쟁을 완전히 차단하지 않는다. 네트워크 파일시스템과 상속 ACL의 보안 의미도 보장 범위 밖이다. 실패 시 새로 생성한 상위 디렉터리는 남을 수 있다.

파일 sync는 수행하지만 상위 디렉터리를 fsync하지 않으므로 전원 손실 후 이름 교체의 영속성을 보증하지 않는다. 강제 종료나 정리 실패 시 비공개 임시 디렉터리가 남을 수 있다. rename 후 정리 실패는 저장된 완성 파일과 함께 명령 오류를 반환할 수 있다. ACL·소유권·기존 inode는 보존하지 않으며 POSIX 권한과 rename 동작에 대한 실제 테스트 범위만 주장한다.

## 호환성과 검증 조건

보고서 스키마/시나리오 버전/CLI 인자는 바꾸지 않는다. 파일 출력 때 stdout은 비우고 요약은 stderr에 둔다. 시나리오 FAIL이 있는 완료 보고서도 저장한 후 종료 코드 2를 반환한다. 입력/실행/저장 실패는 종료 코드 1이며, stdout 모드의 JSON 출력은 유지한다.

실제 파일시스템에서 신규/덮어쓰기 권한, 링크, 비일반 대상, 쓰기·sync·rename 실패 주입과 동시 writer를 확인한다. CLI subprocess는 합성 읽기 전용 RPC와 프로그램 소유의 신규 Anvil Fixture만 사용해 종료 코드 0/1/2와 실제 저장 파일 계약을 검증한다.

Lead 요청 `04816544255946e7a670208926743858`의 proceed 응답을 회수하고 원본·hardlink 보존, 권한, 실패 단계, 정리와 원자적 교체의 한계를 검증 조건으로 적용했다. 표적 검토이며 외부 배포나 자산 취급 승인이 아니다. POSIX 테스트는 표준 `mkfifo` 유틸리티로 FIFO를 생성한다.
