# ADR0044: 읽기 전용 DB 시장 화면

2026-10-22 · 사용자 후속 진행 및 검증 후 push 승인.

## 결정

기존 loopback 미리보기의 `GET /market-data.json`에 명시 `--database` 모드를 추가한다. `--database-env`는 서버가 읽는 비공개 env 파일이며, 지정하면 상속된 writer 접속 설정보다 그 파일을 우선한다. 기본 JSON 모드는 유지한다. 브라우저에는 DB 자격증명·raw 원문·임의 SQL/경로 API를 제공하지 않는다. 수집기는 별도 프로세스이며 웹 조회는 수집/거래/DDL/DML을 실행하지 않는다.

기존 TLS 검증과 runtimeRole/schema/RLS/실효 권한 검사를 적용하고 `access_grant.access_mode=reader`도 강제한다. writer/관리자·상속/열 단위 권한 과다는 거부한다. 단일 READ ONLY REPEATABLE READ transaction에서 registry의 DB 식별자와 고정 표시 registry를 대조하고 최신값/관측/네트워크/요청 상태를 조회한다. 금액·ledger index는 문자열이다. legacy id/groupId/selector·hash·clock·원장 연결·microsecond 관측 시각과 원본 sourceAt을 보존한다. legacy 연결이 없는 신규 유형은 기존 화면 계약으로 꾸미지 않고 오류 처리한다.

## 조회 한도와 실패

화면은 최근30일의 시리즈별 실제 관측을 결정적 `(observed_at,request_id)` 순으로 최대200개 고른다. 여러 시리즈는 전체2400점 예산에 맞춰 시리즈별100~200점으로 줄이며 실제 한도를 응답/화면에 표시한다(기간 밖 최신값은 별도). 한도 이하는 모두, 초과하면 양끝을 포함한 균등 순번 표본이다. 평균·가짜 시각을 만들지 않는다. 최신 정상값은 기간 밖이라도 요약/상세에 유지하며 차트에서 제외한다. 기간 버튼은 DB 조회 시각 기준이고 전체 버튼은 ‘조회 범위’다. 원본 관측 수·표본 여부·조회 범위를 표시한다. 최신 요청 실패/누락과 유지한 정상값을 구분한다. 같은 요청 group의 체인 순위 규칙은 유지한다.

이번 미리보기 한도는 전체24시리즈·최대5000관측·2MiB다(최신값 포함). 초과/registry 불일치/권한/접속 오류는503이다. 시리즈가 늘면 후속 페이지/선택 조회 설계가 필요하며 조용히 일부 자산을 숨기지 않는다. query/transaction timeout을 유지한다. 성공 응답은10초 동안 재사용하고 동시에 들어온 요청은 한 연결/한 작업을 공유한다. 완료/실패 모두 연결을 닫는다. DB 오류 뒤 JSON 자동 전환/자동 재시도는 없다. 브라우저는 이전 성공값과 원래 관측 시각을 유지한다.

수집/scheduler/DB 저장 상태 파일은 JSON snapshot 없이 별도 읽는다. 이 기록은 DB 조회 성공이나 프로세스 생존 증명이 아니며 표시도 분리한다. DB 화면은 등록 밖 공급량 누락 개수를 계산하지 않아 제공하지 않는다고 명시한다.

## 검증

소유 격리 PostgreSQL17에서 실제 reader/writer/owner·정밀 금액/시각·같은 시각의 서로 다른 요청·205→200 실제 표본/양끝·기간 밖 최신값·XRPL 원장·동시 import 중 snapshot 일관성·registry/시리즈 한도·GET 실패/비밀 경로 차단을 검사한다. 별도 단위 검사는 동시 요청 공유/캐시 만료/실패 정리/2MiB/명시 인자를 검증한다. 실제 Supabase reader와 원본 대조 및 Chrome 확인은 최신 인계문에 수량과 결과를 기록한다. 공개 배포와 무제한 수집 운영은 이 결정에 포함하지 않는다.
