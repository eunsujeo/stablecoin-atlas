# ADR0041: 5분 시장 자료 자동 수집

상태: 채택. 사용자 2026-10-22 자동 수집 요청. ADR0037의 수동 실행 제한에서 이 경로만 확장한다.

## 결정

`npm run market:watch`는 웹과 별도 프로세스로 즉시 첫 수집 후 300초 시작 간격으로 기존 collector를 호출한다. 단조 시계로 간격을 계산하고 지연 슬롯은 건너뛴다. 동시 실행·밀린 실행·재시도·자동 재시작·공급자 전환은 없다. 같은 저장소의 `.scheduler-lock`을 배타 생성하고 소유자를 확인한 뒤 정리한다. 기존 수동 수집/build와는 `.writer-lock`으로 경쟁하며 충돌 시 중단한다. 잠금을 시간/PID로 강제 회수하지 않는다.

기본 12회(최대84 GET, 약55분에 마지막 수집) 후 종료한다. `--max-runs 1..288`로 프로세스당 예산을 명시할 수 있다. 최대2016 GET은 프로세스당 상한이며 계정의 일일 크레딧 보장이 아니다. 재실행하면 예산은 새로 시작한다. 공급자 기간/잔여 크레딧/단가가 미확인인 상태에서 무제한 daemon이나 자동 재시작을 구성하지 않는다. 기존5000관측/2MiB 발행 한도도 유지한다.

모든 비SUCCESS 및 예외는 중단한다. 진행 중 수집은 SIGINT/TERM에도 기존120초 예산 내에서 완료/실패를 기록하고 잠금을 정리하며 다음 실행은 하지 않는다. 성공한 게시를 뒤늦은 상태 기록 오류 때문에 취소된 것으로 표시하지 않는다. 실패 시 기존 원본과 마지막 게시 index·관측 시각을 보존한다. 웹에는 안전한 상태·시각·실행 예산만 제공하며 overdue 기록은 생존 보장으로 표시하지 않는다. 키·환경·외부 오류 본문·계정 목록은 노출하지 않는다. 관리형 proxy를 기존 Node 실행 옵션으로 존중한다.

## UI와 저장 경계

웹은60초마다 저장본과 수집 실행 기록을 읽는다. 웹 요청·서버 시작은 수집을 실행하지 않는다. 저장은 기존 projection/JSON publisher이며 PostgreSQL 자동 import나 Supabase 접속은 포함하지 않는다. XRPL 과거 관측은 갱신하지 않는다. 첨부된 CoinGecko·DefiLlama 화면은 추이/네트워크/기간 비교의 참고이며 전체 시장 시총·과거 변화율·거래량/유입량을 추정 생성하지 않는다. 현재 등록3코인의 유통량을 전체 스테이블코인 시장으로 표시하지 않는다.

## 검증

가상 시계와 기존 collector의 모의 응답을 함께 사용해 두300초 관측·정밀 수량·14 GET·예산 종료·동시 scheduler/writer 차단·429 무재시도·지연 슬롯·signal 정리와 상태 검증을 확인한다. 전체 검사는 `npm run check`를 따른다. 실제 실행 결과는 인계문에 구분한다.
