# ADR0074 — 비용 귀속·최종성 증거 계약 설계

## 상태와 범위

2026-10-23 사용자가 ADR0073 인계 뒤 다음 진행을 요청했다. 이번 단위는 [ADR0073](0073-offline-reconciliation-review-fixture.md)의 차단 사유를 해소하려면 필요한 **증거 계약과 향후 검증표의 설계**다. 새 API·DB schema·배분/차감 구현은 추가하지 않는다. 실제 공급자/usage/SQL 호출·legacy 전환·운영 DB·스케줄·웹 연결도 포함하지 않는다.

현재 공급자가 아래 증거를 제공하는지, 어떤 자료가 최종성을 보증하는지는 **UNCONFIRMED**다. 이번에는 공식 문서·계정 조건을 새로 조회하지 않았다. 아래 필드는 내부 요구사항이며 공급자 응답 필드나 현재 지원 기능을 설명하지 않는다. 사람이 채운 선언·hash 일치·가상 자료 검증만으로 공급자 근거나 실제 차감 승인을 만들 수 없다.

[ADR0070](0070-legacy-allium-transition-and-checkpoint-review.md)의 실제 legacy 상태와 [ADR0068](0068-daily-allium-design-and-cost-controls.md)의 예산 산식을 유지한다. 현재 실제 전환은 TRANSITION_BLOCKED·P UNKNOWN·b_i null·c_i=0이며 기존 Lab도 c_i=0이다. 이 문서는 기존 보고서의 UNKNOWN을 변경하지 않는다.

## 증거 묶음의 최소 계약

향후 검토 입력은 다음 자료를 함께 연결해야 한다. 원문은 비공개 저장소에 보존하고 보고서에는 검토된 요약만 싣는다. 원문·키·RPC URL·인증 정보는 Git/웹에 게시하지 않는다.

| 구분 | 필요한 연결 | 충족하지 못할 때 |
| --- | --- | --- |
| 조직 | 안정된 공급자 조직 identity와 키의 소속/유효기간 근거. 키 교체 전후·다른 PC/소비자도 같은 조직으로 연결 | 키 지문만으로 조직을 추정하지 않고 차단 |
| 기간·단위 | 청구·할당·한도기간 각각의 identity, 시작 포함/끝 제외 경계, 원래 시간대/offset·DST 규칙, 정확 EU 단위/정밀도 | UTC 날짜나 청구기간으로 다른 기간을 대체하지 않고 차단 |
| 출처·버전 | 취득 경로/주체와 공급자 출처 근거, 원문 bytes hash/길이, 불변 버전, 원래 관측시각·별도 검토시각 | hash를 진위 인증으로 취급하지 않고 UNKNOWN 유지 |
| 예약 연결 | 조직·fixture/DB epoch·예약·intent·job/operation·송신 ordinal/hash와 공급자 과금 항목의 명시적 연결 | SQL·시각 유사성으로 연결하지 않고 차단 |
| usage 포함 집합 | 특정 불변 usage 버전에서 각 과금 항목이 포함됐다는 근거와 정확한 반영 수량. create/run/status/result/usage 등 비용 범위와 다른 소비자 포함 여부 | aggregate 증분이나 result meta로 배분하지 않고 UNKNOWN 유지 |
| 최종성 | 공급자가 해당 항목/기간의 반영을 확정하는 근거, 지연·진행 중 비용의 처리 범위, 정정/취소 가능성과 버전 계보 | 시간 경과·SUCCEEDED·불리언 선언으로 대신하지 않고 차단 |

수량은 십진 문자열과 bigint로만 다룬다. JSON Number·음수·누락·정밀도 초과·단위 불일치를 0이나 반올림으로 보정하지 않는다. 예약시각·송신시각·비용 발생기간·usage 관측시각·검토시각을 구분하고, 기간을 넘는 반영은 명시적 연결 근거가 없으면 차단한다. 과거 비용 포함 검토가 성공하더라도 새 실행에 필요한 usage 신선도와 공급자 통제 조건은 별도로 충족해야 한다.

## 중복 배분과 후속 상태 전이 조건

이 절은 후속 구현 조건이다. 현재 원장에는 claim이나 비용 차감 이벤트를 추가하지 않는다.

같은 과금 항목의 정체성은 snapshot hash·로컬 파일명·key·root·DB epoch와 독립적으로 추적할 수 있어야 한다. 중첩 usage snapshot에서 같은 항목이 다시 나타나거나 여러 원문이 같은 청구 항목을 나타내도 새 비용으로 만들지 않는다. 공급자 항목 식별자가 없고 대체 연결의 유일성을 입증할 수도 없다면 자동 배분을 열지 않는다. 다른 소비자/원장까지 포함한 조직 공통 소유권과 기존 배분 이력이 없으면 로컬 UNIQUE 제약만으로 충분하다고 보지 않는다.

향후 배분은 검토한 usage 버전·항목·예약·정확 수량·원문/검토 hash·이전 배분 head에 결합해야 한다. 조직 transaction lock과 원자적 claim 아래 동일 항목에 대한 누계가 입증된 반영 수량을 넘지 않도록 검사한다. 동일 요청의 재생은 기존 결과만 반환하고, 다른 예약의 중복 선점이나 충돌하는 입력은 차단한다. 여러 원장에 걸친 단일 권위가 확인되지 않으면 배분하지 않는다.

예약별로 `0 ≤ c_i ≤ b_i`이며, 같은 반영 금액을 둘 이상의 c_i에 사용하지 않는다. c_i는 연결한 usage의 소비량 U에 실제 포함된 금액만 나타낸다. 나중 usage로 교체할 때도 기존 배분 포함 관계와 계보를 재검증하며, 오래된 반영 증거를 새 U에 그대로 적용하지 않는다. 배분 합은 해당 증거가 입증한 항목별 수량과 U를 넘을 수 없으며, aggregate U가 충분하다는 사실만으로 귀속을 입증하지 않는다.

입증된 c_i가 향후 P 계산에서 제외되더라도 L_day/L_period 예약 누계는 줄이지 않는다. b_i 미확인·상한 초과·같은 기간 usage 감소·귀속 불명·증거 정정/취소는 신규 dispatch와 추가 배분을 차단한다. 정정으로 이미 반영한 c_i가 영향을 받으면 원래 이력을 보존하고 조직을 차단하며, 덮어쓰기·자동 환급·기간 초기화로 복구하지 않는다. 정정 반영·미사용 상한 해제·carryover·다른 기간으로의 비용 이월은 별도 미결 정책이다.

## 후속 Fixture의 필수 검증표

아래는 **아직 실행하지 않은 시험 명세**다. 후속 승인이 있는 가상 자료·새 소유 PG Fixture에서 검증하고, 성공해도 공급자 진위/지원·실제 최종성·운영 전환의 증거로 쓰지 않는다.

| 사례 | 기대 결과 |
| --- | --- |
| 완전한 가상 포함 집합·최종성·정확 수량 | 가상 계약의 일관성만 확인. 실제 비용 인증/실행 활성화 없음 |
| 조직 불일치·키 교체 연결 누락·다른 소비자 범위 불명 | 차단, 기존 UNKNOWN·예약 보존 |
| 기간 경계·DST·지연 반영·과거 usage·단위/정밀도 오류 | 명시 연결/조건 없으면 차단. reset/0 대체 없음 |
| aggregate 증가·result meta·단순 최종성 선언만 존재 | 귀속/최종성 UNKNOWN, c_i=0 |
| 중첩 snapshot·동일 항목의 다른 bytes/hash·다른 root/epoch | 동일 항목 중복 배분 차단. 별도 root를 새 예산으로 쓰지 않음 |
| 독립 DB 연결이 같은 항목을 동시 선점 | 입증 수량 이내의 단일 배분, 초과 선점 실패 |
| 같은 요청 재생·다른 예약/수량으로 재사용 | 동일 결과 조회 또는 충돌 차단, 누계 증가 없음 |
| 배분 INSERT/commit ACK 유실·publication 실패 | 신규 사용 차단, 원문/기존 상태 보존. 재전송/환급 없음 |
| DB·원문·배분 이력의 독립 복원·변조·삭제 | trusted head/원문 불일치 차단. 배분 재사용 없음 |
| trusted reference까지 공동 과거 복원 | ADR0071/0072의 최신성 한계 명시. 자체 hash로 해결했다고 주장하지 않음 |
| 정정/취소·usage 감소·비용 상한 초과·새 usage의 포함 관계 상실 | 조직 dispatch/추가 배분 차단. 이력 유지, 자동 c_i 수정/환급 없음 |
| 반복 검토·일자/키/기간 변경 | 현재 읽기 API의 c_i=0·L·UNKNOWN 유지. 자동 이월 해제 없음 |

## 다음 경계와 검증 기록

다음 구현 후보는 위 계약의 누락/충돌을 판정하는 **읽기 전용 가상 증거 검토 Fixture**다. 실제 배분·c_i 변경 없이 필수 근거와 차단 사유의 구분부터 시험한다. 이는 별도 사용자 확인 후 진행하며, 실제 증거 확보나 차감 경로를 승인한 것으로 해석하지 않는다. 공급자 자료에서 계약을 충족할 수 없다면 자동 대사는 계속 차단한다.
