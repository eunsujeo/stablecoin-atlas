# ADR0059 — Allium 기본 공급자와 일별 전송량 저장

사용자는 Allium을 기본 공급자, DeFiLlama를 장애 시 보조로 선택했다. 앞선 공급자 자동 전환 제외에서 사용자 요청한 이 정책은 예외다. 한 대시보드·같은 지표 화면으로 제공한다.

## 이번 구현

검토한 Ethereum 5코인의 최근 Allium 전송량 원문을 오프라인 import해 PostgreSQL `atlas_activity`에 저장하고 전체 현황에 일별 전송량·네트워크·코인별 최신 기준일을 표시한다. 신규 외부 API 호출·자동 SQL 실행은 없다. 브라우저는 DB의 검토된 projection만 읽는다. 원문의 SQL·query/run 식별자·키는 웹/DB projection에 제공하지 않는다.

Allium 원문 해시와 mapper 버전으로 source를 고정하고, 코인·네트워크·날짜별 값은 append-only로 보존한다. 같은 원문 재import는0추가, 수정 원문은 새 source/행으로 보존한다. 최신 선택은 원래 queried_at 기준이며 import 시각으로 오래된 값을 최신으로 만들지 않는다. 같은 원래 조회시각의 충돌값은 거부한다. 겹치는 날짜를 다시 가져와도 각 지표의 최신 한 값만 조회한다. 누락·조정값 null은0이 아니다.

전용 schema의 FORCE RLS·등록된 최소 권한 reader/writer를 사용한다. writer는 INSERT만, reader는 SELECT만 허용하고 원본은 비공개 파일에 보존한다. 기존 market/history/registration 자료를 변경하지 않는다.

## 기본·보조 선택 정책

Allium을 기본으로 사용한다. 장애 중 정상 저장본이 있으면 그 값과 원래 기준일을 유지한다. 동일 지표·단위·범위의 보조 자료만 조회 구간 전체로 전환할 수 있으며 `보조 자료` 상태를 표시한다. 그래프 중간에 서로 다른 공급자 정의를 이어 붙이지 않는다. 보조 자료의 기준일이 더 오래되거나 요청 범위가 다르면 사용하지 않는다. 빈 행과 장애를 구분한다.

현재 DeFiLlama에는 검증된 동일 전송량 경로가 없으므로 전송량은 마지막 정상 Allium 저장본을 유지하고, 양쪽 모두 없으면 미확보로 표시한다. 일반 유통량·조정 유통량·브리지 순조정은 같은 지표로 간주하지 않는다. 공급량의 전체 기본 경로 전환과 DeFiLlama 보조 연결은 다른 네트워크 지원/정의 확인 후 구현할 후속 범위이며, 이번 단계에서 완료라고 표시하지 않는다. [실측 한계](../research/allium-samples/followup.md)를 보존한다.

## 검증

실제 PG17에서 reader 쓰기·writer 수정 거부, 같은 원문 재import·동시 import·이력 수정/구시각/충돌·null·롤백을 검증한다. 기존 검토 원문 import 후 live reader로 수량/기준일을 확인한다. UI 새로고침·로딩·조회 실패의 마지막 정상 자료·모바일을 확인하고 전체 check를 실행한다.
