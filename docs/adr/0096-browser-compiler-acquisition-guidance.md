# ADR 0096: 공식 compiler 거절 시 브라우저 후속 경로

## 사용자 지시와 결정

2026-10-25 사용자가 공식 compiler 취득이 거절되면 브라우저를 띄워 진행하도록 가이드를 요청했다. [실행 가이드](../COMPILER_BROWSER_ACQUISITION.md)를 정본으로 삼는다. 승인된 동일 버전/공식 host/고정 파일의 직접 요청이 거절되면, 후속 취득 작업에서 새 임시 브라우저 창으로 이어가는 것을 기본 경로로 한다. 방식 변경만을 이유로 같은 사용자 승인을 반복 요청하지 않는다.

이번 작업은 문서/AGENTS 변경이며 실제 브라우저 송신·compiler 취득·profile 변경은0이다. 현재 USDT0.4.18의 브라우저 단계도 아직 실행하지 않았다. 이전 단발 실패의 소비/결과를 재사용하거나 성공으로 바꾸지 않는다.

## 한도와 범위

직접 최대2GET/34MiB/120초와 별도 새 소비 root의 브라우저 최대2GET/34MiB/120초를 구분한다. 한 취득 작업에서 두 단계 합계최대4GET/68MiB/240초이며, 각 요청30초·각 단계 재시도/redirect/host 전환0이다. metadata 성공과 path/버전/두 hash 확인 후에만 artifact를 받는다. 현재 직접 단계의 실제 사용은1GET이고 소비 완료다. 새 브라우저 단계는 최대1회다.

사용자가 볼 수 있는 임시 창을 기본으로 하며 실제 headless 실행과 혼동하지 않는다. 요청 gate·페이지 script 차단·원본 hash·소유권/권한·staging/worker·전체 버전 검증과 사설 Fixture 경계를 유지한다. 계측 대상 문서 요청과 브라우저 자체 통신 범위를 구분한다. 브라우저도 거절되면 종료하고 추가 경로를 자동 시도하지 않는다.

이 예외는 개발용 공식 compiler 취득에만 적용한다. 제품 자동 다운로드·임의 compiler 경로/URL·외부 빌드 스크립트·유료 공급자 API/RPC·로그인/키·실제 토큰 분석·서명/거래·DB/UI로 확대하지 않는다. ADR0095의 당시 실패 경계와 결과는 과거 기록으로 보존하고, 새 브라우저 단계에는 이번 후속 지시와 별도 소비를 연결한다.
