# 입금 경로와 반복 운영 패턴

## 사용자 목표와 변경
기존 분석도 거래 목록 중심이라 Binance→Upbit 입금의 출발·목적지와 이후 주소의
반복적인 자금 운영을 이해하기 어려웠다. 기존 Atlas 디자인을 유지하면서
기본 화면에 선택 가능한 출발/입금/후속 수신 경로를 배치했다.
사용자가 설명한 거래소 문맥은 정확한 TXID+송신+수신 주소에만 연결하며
USER_PROVIDED/소유권 독립 미확인으로 명시한다. 개인 신원은 포함하지 않는다.

선택 주소의 별도 활동 프로필: 다수 수신/소수 전달/다수 배분,
상대별 수신·송금 건수와 금액, 동일 금액 반복, 시간 분포와 TXID.
관측 역할과 Hot/Cold 키 보관 판정을 분리했다. 단기 다중 송금은 핫월렛형 운영의
후보이며 실제 온라인 키 증거가 아니다. 휴면·미수집·단기잔액은 콜드 근거가 아니다.
정확한 휴리스틱과 한계는 docs/WALLET_FLOW.md를 따른다.

## 관측
출발 주소는 해당 송금 외 이력이 미수집이므로 소속·핫 역할을 추가 추정하지 않음.
입금 주소: 1개 상대 수신 → 1개 상대 전달, 336초 간격. 반복 자동화 확정 안 함.
후속 주소: 7개 상대 수신/30개 상대 송금. 집금·배분 허브 후보.
1시간 미만 구간20개 송금 거래/20수신 상대는 핫월렛형 활동의 단서.
같은 수신 상대에 두 번 이상 송금한 근거는 없음. 10USDT 송금2건은 서로 다른 상대.
관측 기간은 제한돼 평소/장기 패턴으로 일반화하지 않는다.
이번 작업 공급자 호출0, 기존44거래43이벤트 snapshot 바이트 유지.
DB/Collector/FX/자동수집/보안 정책 변경0.

## 검증 및 실패 처리
Lead submit은 identity/repository mismatch로 ID 생성 전 실패; 승인 아님, 재시도/위임0.
새 프로필 테스트와 기존 Wallet Flow 테스트19pass.
브라우저에서 기본 선택 후속 주소와 우측 주소 상세를 일치시켰다.
후속 주소의12상대 관계도가 노트북 첫 화면을 벗어나던 문제는 경로·관계도에서
중복 KPI행을 감춰 분석 영역을 우선 배치해 해결한다.
네이티브 버튼 키보드 테스트는 Enter의 실제 text/keyUp 이벤트를 포함한다.
검증 결과와 운영 반영은 인계문에 기록한다.

로컬 최종 검증: npm run check rc0 / 990 pass / 0 fail / 8 skip.
Wallet Flow19pass. 브라우저 실제 관측/fixture 1440×900,1280×800,390×844,
양테마5뷰, 경로 노드 키보드·선택 상태·상세 동기화·범위/빈값/기존필터 PASS.
별도 실제 자료 검사로 Binance→Upbit 사용자 문맥, 허브 후보→입금 전달 후보
선택 전환, 핫 운영 후보 표현을 확인했다. 운영 배포 전 snapshot 변경0도 확인.
전체 스크린샷에서 우측 역할 근거 TXID가 지나치게 길게 나열되는 문제를 발견해
근거 목록을 펼침형으로 바꾸고 동일 브라우저 검사를 재실행했다.
