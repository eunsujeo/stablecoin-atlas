# 자산 프로필 재구성

사용자의 “자산프로필 새로 구성” 요청을 [ADR0100](../adr/0100-reviewed-source-asset-profiles.md)의 로컬 정적 표시 범위에서 구현했다. 기존 데이터의 5토큰·8배포와 전체 연결 UNKNOWN을 유지한다.

## 구성과 수행 경로

기본 `/#assets`와 `/atlas.html#assets`에 같은 자산 목록·검색·상세 화면을 적용했다. 토큰/체인/주소로 검색하고 자산을 선택한 뒤 해당 자산의 네트워크를 선택한다. 검색 결과가 없어도 현재 상세는 유지하며 빈 목록 안내를 표시한다. 자산마다 마지막으로 선택한 네트워크를 화면 메모리에 기억한다.

개요는 네트워크·chainId·주소·검토 기준일과 소스 연결/원본 관측을, 기능·권한은 기존 함수/관리 조건을, 근거·한계는 저장 관측/기존 제한을 보여준다. 방향키·Home/End로 탭을 이동할 수 있다. 모바일에서는 자산 목록을 작은 2열 버튼으로 구성한다. 기존 관측 보고서는 별도로 유지하며 이름만으로 연구 프로필에 연결하지 않는다.

공개 발췌 데이터·생성 문서와 원본 보고서를 변경하지 않았다. 외부 취득·RPC·compiler 실행·DB 변경은 없다. Sites 스킬의 로컬 미리보기 절차를 사용했고 호스팅 등록/배포는 수행하지 않았다.

## 확인·수정과 확보 범위

최초 편집 도구가 같은 파일의 삭제/추가 패치 형식을 거절해 파일 쓰기로 적용했다. 정적 확인에서 기본 화면에는 Atlas의 accent 변수가 없음을 확인하고 테마별 기존 색상을 사용하는 fallback을 추가했다. 브라우저에서 390px 화면의 자산 목록 높이를 확인한 뒤 모바일 버튼을 줄였다. 데이터·판정 오류나 테스트 실패로 인한 재시도는 없었다.

새로 확보한 것은 화면 구성/조작 검증 결과다. 현재 배포 연결·공식 지원·권한·실제 실행의 미확인은 이전과 동일하다. USDC 불일치, USDT 실패, JPYC 프록시 한정 확인과 타체인 미관측, Kaia 부분 일치, JPYSC 자동 분석 절단을 보존했다.

## 검증과 재현

1. `npm run ui -- --port 4174`로 독립 로컬 JSON 서버를 실행한다.
2. 설치된 macOS Google Chrome으로 `node tools/source-review-browser-check.mjs http://127.0.0.1:4174`를 실행한다. 외부 요청을 차단하며 두 화면의 8배포·모든 탭 원문·검색/빈 결과·자산별 체인 기억·키보드/포커스·보고서 수 보존·근거503 격리·다크/라이트·390px 배치를 확인한다. 정적 HTML 확인과 구분해 실제 렌더링/정상 응답을 검사한다.
3. `npm run check`, `git diff --check`를 실행한다. 실행 rc와 pass/fail 수는 [인계문](../handoff/2026-10-25-asset-profile-redesign.md)에 기록한다.

브라우저 결과: `.state/agent-logs/profile-redesign-browser.log`. 화면 캡처: `.state/profile-redesign-{legacy,atlas}-{dark,light}[-mobile].png`. 전체 검사: `.state/agent-logs/profile-redesign-check.log`. 임시 Chrome/profile과 검증용4174 서버는 종료하며 사용자용4173 서버는 유지한다.
