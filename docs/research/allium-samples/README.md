# Allium 실제 조회 결과 — 2026-10-23

후속: [최근 기간 전송량·공급량 차이 분석](followup.md)에서 Ethereum 5코인의 10/21 전송량을 확보했다. 이 문서의 10/22 단일 날짜 0행 기록은 그대로 보존한다.

사용자가 설정한 키와 소량 조회 진행 요청으로 Explorer SELECT 4개를 각각 저장·실행했다. 4개 모두 HTTP 200·실행 success를 확인했다. 재실행·자동 재시도·연산 자원 생성/변경·DB 저장·대시보드 교체는 하지 않았다. 사용자 설명상 넉넉한 사용 범위로 진행했으며 무료·무제한을 API로 확인한 것은 아니다.

Allium 등록부의 JPYC·JPYSC `is_verified`는 false다. JPYSC 공급량의 `_metadata.integration_status`는 `prod_ncs_unverified`다. 공급자 품질 표시는 보존하며 제품 PASS/FAIL로 해석하지 않는다. JPYC는 기존 현행 전자결제수단형 주소와 대조했고 JPYC Prepaid로 교체하지 않았다.

## 검증과 제한

- 결과 15행의 주소·코인·날짜·중복을 검사했다. 수량 문자열을 유지하고 발행·소각 원시 정수와 decimals 정규화가 일치하는지 오프라인 검증했다. 누락을 0으로 바꾸지 않았다.
- 공급량·전송량은 SQL `TO_VARCHAR`를 사용했다. 결과가 문자열이어도 원본 자료형의 정밀도 손실을 복구하지는 않는다. 원본 수량 컬럼의 자료형은 아직 조회하지 않았으므로 컨트랙트의 최소 단위까지 정확하다고 표시하지 않는다. 발행·소각은 제공된 `raw_amount_str`·`amount_str`를 그대로 사용했다.
- 공급량 날짜·이벤트 시각은 응답에서 `TIMESTAMP_NTZ`다. 조회 결과 취득 시각과 일별 집계 경계를 구분한다. 원본 집계 타임존·일 마감 시각은 미확인이며 같은 날짜라는 이유로 같은 관측이라고 단정하지 않는다.
- SQL LIMIT와 코인당 표본 제한은 출력량 제한이다. 스캔량·과금 상한을 보장하지 않는다. 응답에 기록된 4회 실행 사용량 합계는 약 **0.19515 Explorer units**이며 금액이나 잔여량을 뜻하지 않는다. 사용량 API는 성공했으나 할당 기간·주기가 null이고 할당량이 0이어서 잔여 한도를 추론하지 않았다.
- 각 쿼리 상태 조회는 최대 10회·간격 2초, 개별 HTTP 요청 제한 20초·응답 2MiB로 제한했다. 이번에는 모두 제한 내 종료했다. 과금 설정·연산 프로필을 생성하거나 변경하지 않았다.

[observations.json](observations.json)은 검토한 결과·정확한 차이·응답/실행 SQL 해시를 담는다. 원문과 계정 내부 query/run 식별자는 비공개 `.state`에만 보존했다. SQL 파일의 실행 상태 설명 주석은 조회 후 갱신했으며 실행 SQL 해시는 실제 응답의 SQL 기준이다. 키·계정 식별자는 공개 자료에 포함하지 않는다.

## 다음 연결 조건

1. 전송량 0행의 원인과 실제 최신 제공 날짜를 확인한다. 다른 기간을 조회하면 별도 관측으로 기록한다.
2. USDC·USDT 유통량 차이의 정의·시각을 대조한다. 전체 네트워크 등록 정보와 공급량을 별도로 확인한 후 상위 10개를 선정한다. XRPL·TRON·Solana 및 다른 네트워크 지원은 이번 표본으로 확인하지 않았다.
3. 자료형·날짜 경계·누락/수정 정책을 확정한 뒤 기존 DB와 다른 공급자 키로 수집 이력을 추가한다. 공급량, 조정 유통량, 발행·소각 이벤트, 전송량을 별도 지표로 둔다. 전송량을 매매 거래량으로 표시하지 않는다.
4. 최초 연결은 저장본 비교 화면으로 검토하고, 공급자와 정의가 다른 시계열을 이어 붙이거나 자동 전환하지 않는다.
