모두 최신 행은 **2026-10-21**이며 10/22 행은 없었다. 첫 조회가 10/22만 요청해 비어 있던 결과와 일치한다. 집계 완료 시각·업데이트 SLA는 미확인으로, 항상 이틀 지연이라고 단정하지 않는다. JPYSC의 중간 누락도 활동량 0으로 보간하지 않는다.

## 유통량의 브리지·준비금 처리

고정 DeFiLlama 소스는 체인 유통량에 발행 잔액과 유입 브리지 물량을 더하고 미유통 준비금과 다른 체인으로 건너간 물량을 뺀다. 원래 컨트랙트의 브리지 담보 잔액과 그 체인의 경제적 유통량은 같지 않다. Allium 일반/조정 유통량도 다른 정의이므로 치환하지 않는다.

저장 원문의 압축을 풀고 SHA-256을 검증한 뒤 10/22 수량을 대조했다:

| 코인 | 미유통 준비금 | 원문 브리지 상세의 유출 합계 | 계산값−저장 유통량 잔차 |
| --- | ---: | ---: | ---: |
| USDC | 86,511,697.181989 | 3,036,266,203.42862527460 | +263,418,148.05935717540 |
| USDT | 2,915,785,071.305825 | 12,276,175,674.939430391 | +552,607,059.650265679 |

계산값은 `minted − unreleased + 유입 − 상세 유출 합계`다. **브리지 상세만으로 저장 유통량을 완전히 재구성하지 못했다.** 잔차는 반올림 수준이 아니며 상세 누락·추가 조정·실제 운영 소스 버전 등을 더 확인해야 한다. 특정 브리지·지갑 때문이라고 확정하지 않는다. 검토한 커밋이 원문 생성 당시 실제 배포 버전이라는 증거도 없다.

USDT의 Allium 총량−일반 유통량은 DeFiLlama 미유통 준비금과 매우 가깝지만 DeFiLlama 체인 유통량에는 그 밖의 브리지 순조정이 존재한다. **날짜 경계와 유통량 정의를 구분해야 한다는 근거는 확보했지만 모든 차이의 정확한 원인은 미해결**이다.

## 오류·검증·연결 조건

새 실행은 실패 포함 3회다. 최초 최근 전송량 SQL은 `Query not allowed. Invalid query`로 실패했다. 소유한 같은 run의 메타데이터를 확인하고 원문을 보존했다. `SYSTEM$TYPEOF`를 제거한 별도 교정 SQL은 성공했으나 일반적 함수 차단 정책으로 확정하지 않는다. Snowflake 함수 지원과 Allium SQL 허용 정책은 같지 않다. 실패 run을 재실행하지 않았다.

공급량 SQL도 자료형 확인 항목을 실행 전에 제거했다. 원본 수량 컬럼 자료형은 여전히 미확보다. 문자열 반환이 원천 FLOAT 손실을 복구하거나 최소 토큰 단위까지 정확하다고 주장하지 않는다. 74행의 주소·기간·중복·십진 문자열·null을 검증했다. HTTP 20초·2MiB, 상태 조회 최대 10회·2초 간격을 유지했다. 계정 내부 식별자는 공개하지 않았다.

다음 저장/조회 설계에는 다음 조건을 적용한다:

- 전송량에 코인/네트워크별 최신 확보일을 표시한다. 공급량 최신일과 같다고 가정하거나 현재 24시간 매매 거래량 열에 넣지 않는다.
- 일별 수집은 최근 며칠을 겹쳐 읽어 늦은 집계를 반영한다. `(공급자, 발행 자산, 지표, 원본 날짜)`로 중복을 막고 값 수정은 원문 해시·취득 시각과 함께 이력으로 보존한다. 날짜 이동·누락 0 처리·이전 값의 새 날짜 복제는 하지 않는다.
- 총공급량·일반/조정 유통량·체인 간 경제적 배분을 분리한다. 다른 정의의 공급자 값을 같은 시계열에 이어 붙이거나 자동 전환하지 않는다.
- 다른 승인 네트워크의 지원과 Allium 별도 저장/조회 경로를 다음으로 검토한다. 전체 상위 10개가 확인됐다고 표시하지 않는다.
