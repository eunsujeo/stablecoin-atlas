# 전체 현황의 소스 확인 현황 연결

## 요청과 구현

사용자가 전체 현황의 기술 검증 현황에도 소스 확인 기준을 반영하도록 요청했다. 기존 화면은 저장된 읽기 보고서만 집계해 소스로 확인 완료한 기능·권한을 보여주지 않았다. [ADR0100](../adr/0100-reviewed-source-asset-profiles.md)에 따라 자산 프로필과 같은 정적 데이터를 사용해 5자산·4네트워크·8프로필의 소스 확인 현황을 표시했다.

기술 검증 영역 상단에 자산/네트워크/확인 완료 프로필 수와 확인 기준을 제공한다. 표에는 각 프로필의 전송·승인·발행 조건과 발행사 제어·권한 조건, 소스 확인 완료, 검토일, 발췌 근거 링크를 표시한다. 직접 실행·현재 권한 행사를 추가 완료조건으로 요구하지 않는다. 기존 읽기 결과·점수·랭킹과 산정 정책은 접힌 실행 기록 안에 그대로 유지한다. 소스 확인은 기존 PASS에 합산하지 않는다. 저장 읽기 로드가 실패해도 소스 확인 현황은 표시한다.

## 수행 경로와 수정

HTML에 소스 확인 요약/표와 접힌 읽기 기록을 구성하고 overview.js에서 기존 공개 소스 데이터를 렌더링했다. 별도 RPC·API·compiler·DB 변경·실제 점수 재산정은 없다. 원본 시각·실패/불일치·제품 판정을 보존했다.

첫 브라우저 검사는 통과했지만 실제 캡처를 확인하니 공통 표의 nowrap 스타일 때문에 긴 조건이 옆 열과 겹쳤다. 이 표에만 줄바꿈/행간을 적용해 수정하고 렌더링을 다시 확인했다. 문서 패치의 잘못된 문맥 지정은 적용 전에 거절되어 정확한 절 제목으로 수정했다. 자료 부족/새 취득 실패로 해석하지 않는다.

## 검증과 재현

`npm run ui -- --port 4174`로 로컬 서버를 시작한 뒤 `node tools/source-review-browser-check.mjs http://127.0.0.1:4174`를 실행한다. 실제 Chrome 렌더링에서 8행 전체 내용/확인 상태/근거 링크, 5/4/8 집계, 읽기 판정 원본 집계와 동일함, 읽기 기록 기본 접힘, 근거503 격리, 다크/라이트·1440/390px·외부요청0·JS오류0을 확인한다. 정적 HTML 정상 응답과 렌더링 검증을 구분한다.

`node --check web/overview.js`, `npm run check`, `git diff --check`를 수행한다. 최종 rc·pass/fail은 [인계문](../handoff/2026-10-25-overview-source-status.md)에 기록한다. 로그는 `.state/agent-logs/overview-source-{browser,check}.log`, 캡처는 `.state/overview-source-{dark,light}-{1440,390}.png`다. 검증용 서버/Chrome은 종료하고 사용자용4173은 유지한다.
