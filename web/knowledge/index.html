합의·확정 장면의 단순화

네트워크의 8개 노드는 전달 과정을 설명하는 표본입니다. 아래 12칸은 전체 활성 지분을 동일 가중치로 나눈 교육용 묶음으로, 노드 수·위원회 크기·실제 ETH 잔액이 아닙니다. 거래와 배정은 고정된 가상 예시이며 실시간 체인에 연결하지 않습니다.

정상적인 연속 체크포인트 경로만 다룹니다. 실제 EVM 실행·BLS 서명·RANDAO 계산, 모든 fork-choice/FFG 분기, MEV/PBS, slashing과 장기 inactivity leak은 구현하지 않습니다. 오프라인만으로 slashing이 발생한다고 설명하지 않습니다.

합의 장면의 시간과 투표

슬롯은 12초, epoch는 32슬롯입니다. 첫 장면의 attestation은 배정된 노드의 head 및 source/target 관점을 설명하고, 뒤의 막대는 epoch 전체의 지분을 집계합니다. 생성·수신·검증·정당화·최종 확정은 서로 다른 상태입니다.

시작 전 C99가 justified라는 전제를 둡니다. 충분한 지지가 있는 두 epoch 경계에서 C100의 상태가 바뀝니다. 장애에서는 분모를 온라인 지분으로 줄이지 않습니다.

블록 생성과 Fork 모형의 범위

블록 생성 장면은 6개 슬롯 중 제안자 오프라인으로 1개가 비는 고정 예시입니다. B는 가상 블록 이름, #는 실행 블록 높이, C는 에포크와 블록 root를 묶는 체크포인트입니다.

Fork 장면은 검증된 후보와 서명을 전제하고, 각 검증자의 최신 메시지와 지분 가중치로 하위 가지를 비교합니다. 최신 메시지가 영향을 주는 시점은 해당 attestation 슬롯 이후입니다. 같은 에포크에 같은 검증자가 표를 바꾸거나 반복 합산하지 않습니다. 비교 시점에는 proposer boost가 만료되었습니다. 전체 viability, BLS, 실행·데이터 가용성 검증을 구현한 클라이언트가 아닙니다.

같은 부모에서 서로 다른 슬롯의 후보가 생기는 예시이며 이중 제안을 정상 동작으로 묘사하지 않습니다. Head 선택에 2/3 기준을 적용하지 않습니다. 확정된 과거는 고정하며 정당화된 기준점의 후손에서만 선택합니다.

합의·확정 학습의 범위

관찰 노드가 받은 최신 투표와 체인 블록에 반영된 Target 지지를 구분합니다. Head는 자식 가지의 유효 지분으로 선택하며 2/3 문턱을 사용하지 않습니다. Source/Target 지지와 FFG 연결 조건은 별도로 확인합니다. 가상 검증자6명·지분5/2/2/1/1/1, 초기 C99 정당화/C98 확정을 사용합니다.

유효성이 확인된 고정 후보, proposer boost가 없는 슬롯 이후 관점입니다. 전체 fork-choice Store·unrealized checkpoint 처리·서명 검증·위원회 선정·보상·inactivity leak을 구현하지 않습니다. 투표 지연은 관찰 구간 내 미도착이며 오프라인은 서명하지 않음입니다. 장기 장애 뒤 영원히 최종성이 회복되지 않는다는 뜻은 아닙니다. 최종 장면은 직전 Epoch의 지지를 보여주며 새 Head 생성과 구분합니다.

Epoch 모형의 범위

정상·슬롯 누락·Finality 지연을 비교합니다. 시작 전 C99는 정당화, C98은 확정됐다고 가정합니다. 검증자6명의 가상 유효 지분은5·2·2·1·1·1단위이며 실제 ETH가 아닙니다. 블록 서명과 실행의 유효성을 전제로, 미슬래시 참여·Source/Target·포함 시점·지분 중복을 검사하고 FFG의4개 정당화 비트 조건을 계산합니다.

현재 안정 사양의 Fulu 변경 범위와 Altair 참여 플래그 처리, 상속되는 FFG 조건을 참고했습니다. 실제 BLS/RANDAO·위원회 계산·보상/페널티 금액·validator activation/exit·inactivity leak 전체를 구현한 클라이언트는 아닙니다. 배정표·활성 집합·유효 지분은 고정 교육 예시입니다.

거래 모형과 공식 문서

서명·EVM 실행·Receipt는 교육용 상태입니다. TX03의 revert는 블록 무효와 다릅니다. Receipt 원문을 거래 목록에 넣지 않으며 실행 결과의 root와 거래 목록을 구분합니다. 외부 builder가 페이로드를 구성할 수도 있습니다. 노드 A/B의 서로 다른 관측과 보관 정책을 단순화했습니다.
